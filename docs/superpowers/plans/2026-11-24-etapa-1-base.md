# Etapa 1: base do core-bank

**Objetivo:** cadastro, login, renovação de sessão, contas, razão contábil, depósito simulado e
extrato, com testes em PostgreSQL real.

**Fonte:** [especificação](../specs/2026-11-24-lastro-bank-design.md), seções 2, 3, 4 e 7.

## Decisões

- O saldo é atualizado por trigger a partir dos lançamentos. O código Java não escreve em
  `balance_cents`, e o banco recusa quem tentar.
- `LedgerService.post` exige uma transação já aberta: quem chama decide o que é atômico.
- Depósito exige `Idempotency-Key`, guardada em `ledger_transaction.external_ref`. A tabela geral
  de idempotência vem com as transferências, na etapa 2.
- Login errado, conta bloqueada e e-mail inexistente devolvem a mesma resposta.
- Número quebrado em campo de centavos é recusado, e não arredondado.
